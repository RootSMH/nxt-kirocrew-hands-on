# Week 04 · 문서로 답하게 하기

빛담 동아리의 가을사진전(E04)을 준비합니다. 학교와 동아리의 문서에서 적용 조건을 찾고, 참가 신청과 회계를 계산해 근거가 있는 운영 판단을 남깁니다.

## 자료 받기

지난주 사용한 본인의 복제 저장소에서 개인 변경 사항을 먼저 확인·커밋한 뒤 업스트림 자료를 받습니다.

```bash
git pull --no-rebase --no-edit upstream main
```

Crew의 작업 폴더는 `class/kookmin-2026-2/ai-platform-development/week04`로 연결합니다.

## 파일 역할

| 위치 | 내용 | 사용 시점 |
|---|---|---|
| [documents/](documents/) | 학교 지침·동아리 규칙·승인서·회의 메모·회계 기준 8개 | 처음에 지식 소스로 등록 |
| [data/참가신청.csv](data/참가신청.csv) | E04 참가 신청 200건 | 전체 파일을 Python으로 계산 |
| [data/회계내역.csv](data/회계내역.csv) | E01~E04 네 행사의 처리 완료 거래 120건 | 행사와 재원, 거래 유형을 구분해 계산 |
| [data/구매계획.csv](data/구매계획.csv) | 앞으로 구매할 물품 12개 항목 | 이미 처리한 회계와 구분해 계산 |
| [updates/](updates/) | 정원 변경 승인서 1개 | 후반 실험에서 추가 |
| [submissions/](submissions/) | 각자 만든 결과를 저장할 폴더 | 실습 중 저장하고 자기 포크에 제출 |

## 진행 순서

1. 처음에는 **documents 폴더만** Knowledge Library의 지식 소스로 등록합니다. 파일별 처리 상태와 실제 검색 결과를 확인합니다.
2. 찾은 문서의 원문·문서 ID·적용 조건을 확인하고, 자료로 결정할 수 없는 질문도 해봅니다.
3. data의 CSV 3개는 Python으로 **원본 전체를** 읽어 계산합니다. 회계 기준의 기초 잔액·환불 부호·행사 범위를 적용하고 실행 결과를 확인합니다.
4. 처음 판단한 운영 보고서와 계산 코드·집계 결과를 submissions에 저장합니다.
5. 수업 후반에 updates의 변경 승인서를 documents에 복사합니다. 검색 가능한 상태가 된 뒤 같은 질문을 다시 하고, 바뀐 판단과 유지되는 수치를 비교합니다.
6. 직접 만든 질문 3개로 답변을 검증하고, 변경 후 보고서와 검증 기록을 저장합니다.

`week04` 전체를 처음부터 지식 소스로 등록하면 후반에 사용할 변경 승인서까지 함께 들어갈 수 있습니다. 변경 전후를 비교할 수 있도록 처음에는 `updates/`를 등록하지 않습니다.

초기 질문: 빛담 가을사진전(E04)의 승인된 참가 정원은 몇 명인가요? 출처와 조항을 함께 보여주세요.

## 저장과 제출

submissions에는 처음 보고서, 변경 후 보고서, 계산 코드, 집계 결과, 개인 질문 검증 기록을 남깁니다. 형식과 파일명은 자유지만 판단·수치·출처·확인 필요 사항을 알아볼 수 있어야 합니다.

원본 CSV는 보존합니다. 저장한 파일을 직접 열어 확인한 뒤 이번 실습 결과만 커밋하고 본인의 `origin` 포크에 Push합니다. GitHub에서도 실제 파일과 내용을 확인합니다.
