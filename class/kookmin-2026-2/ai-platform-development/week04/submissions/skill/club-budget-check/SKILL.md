# club-budget-check

동아리 행사 회계·참가·구매계획을 한 번에 집계하는 **결정론적** 스킬.
같은 입력이면 항상 같은 결과가 나오고, 네트워크나 외부 패키지를 쓰지 않는다.
원본 CSV는 **읽기 전용**이며 결과 JSON만 저장한다(BOM 없는 UTF-8, 스크립트가 직접 쓴다 — PowerShell `Out-File`은 BOM을 붙여 한글이 깨진다).

> 이 스킬은 **집계·판단 근거 계산**만 한다. 표시용 HTML 변환은 `data-to-html` 스킬의 몫이다.

## 무엇을 집계하나

| 항목 | 내용 | 근거 조항 |
|---|---|---|
| 참가 상태별 인원 | 전체 + 대상 행사별 (확정/대기/취소 등) | — |
| 확정자 선택 | 대상 행사 **확정자**의 선택 열별 분포(인화체험·식음료 등, 자동감지) | CLUB-01 제1조 |
| 재원별 현재 잔액 | 기초 + 수입 + 환불입금 − 지출 − 환불지급 (전체 행사) | ACCOUNT-01 제2·3조 |
| 행사 순지출 | 지출 + 환불지급 − 환불입금 (**수입 제외**, 대상 행사만) | ACCOUNT-01 제3조 |
| 구매계획 예정비용 | '참가자'=확정인원×계수, '고정'=계수. 예정비용=단가×수량 | ACCOUNT-01 제5조 |

- 구매계획은 **앞으로 필요한 수량**이며 회계 잔액/지급 비용에 **합산하지 않는다**(ACCOUNT-01 제4조). 시나리오 예정치일 뿐이다.
- 대기자는 전환 전까지 확정 인원에 더하지 않는다(CLUB-01 제3조). 확정자만 집계 기준이다.

## 입력 CSV의 필수 컬럼

- **참가신청**: `신청_ID, 행사_ID, 신청상태` (+ 선택 열: 이름/신청일 제외 나머지를 확정자 선택으로 자동 집계)
- **회계내역**: `거래_ID, 행사_ID, 재원, 유형, 금액` (유형: 수입/지출/환불입금/환불지급)
- **구매계획**: `항목_ID, 물품, 수량기준, 계수, 단가, 예정재원` (수량기준: 참가자/고정)

## 실행

```bash
cd scripts

python club_budget_check.py \
  --apply  ../../../class/.../week04/data/참가신청.csv \
  --ledger ../../../class/.../week04/data/회계내역.csv \
  --plan   ../../../class/.../week04/data/구매계획.csv \
  --event  E04 \
  --capacities 140,160,180 \
  --expect "확정인원=140" \
  -o ../../../class/.../week04/submissions/집계결과.json
```

### 옵션

- `--apply/--ledger/--plan` (필수): 세 CSV 경로
- `--event` (필수): 집계 대상 행사_ID (예: `E04`)
- `--capacities`: 구매 시나리오 인원 쉼표구분(예: `140,160,180`). 비우면 **확정 인원 하나만** 계산
- `--opening`: 기초잔액 재정의 `재원=금액` 쉼표구분(기본 `학교지원금=0,동아리회비=800000`)
- `--choice-cols`: 확정자 선택 집계 열 지정. 비우면 자동감지(신청_ID/행사_ID/이름/신청상태/신청일 제외)
- `-o/--output`: 결과 JSON 경로(BOM 없는 UTF-8). 없으면 stdout
- `--expect`: 크로스체크. `확정인원=140` 형태. 불일치 시 **종료 코드 2**

### 종료 코드

- `0` 정상
- `1` 입력 오류(파일 없음·필수 컬럼 누락·빈 CSV·신청_ID 중복·정수 아닌 금액)
- `2` `--expect` 크로스체크 불일치

## 검증 규칙 (임의 처리 금지)

- 부호 규정(제2조)에 없는 **회계 유형** → 잔액 미반영 + `확인_필요`
- 기초잔액이 정의되지 않은 **재원** → 기초 0 가정 + `확인_필요`
- **음수 금액** 거래 → 제2조상 금액은 양의 정수이므로 `확인_필요`
- **미지 수량기준**(참가자/고정 외) → 해당 항목 비용 계산 보류 + `확인_필요`
- 확인되지 않은 것은 결과 JSON의 `확인_필요` 목록에 남긴다.

## 판단은 근거와 함께

집계 결과로 운영 판단을 남길 때는 문서 ID·조항을 함께 표기한다(CLUB-01 제4조: 제안과 실제 처리 결과를 구분하고 판단 근거를 문서 ID·조항으로 남긴다). 정원은 홍보 문구가 아니라 장소 사용 승인서에 따른다(APPROVAL-SPACE-04 / RULE-02 제1조).

Python은 환경에 따라 `python` 또는 `py`(이 환경은 `python`, 3.12 확인).
