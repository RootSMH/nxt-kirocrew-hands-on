단계 01

이번 주 자료 받기

이미 Clone한 저장소에서 강사가 추가한 자료를 받습니다.

  1. 터미널의 현재 폴더가 nxt-kirocrew-hands-on 최상위인지 확인합니다.
  2. git status로 현재 변경을 확인합니다. 수정한 파일이 있으면 내용을 살펴보고 본인 작업만 먼저 커밋합니다.
  3. git remote -v에서 upstream이 수업 원본, origin이 자신의 포크인지 확인합니다.
  4. 이 저장소에서 처음 한 번, git config --local pull.rebase false로 내 작업과 새 자료를 합칠 방식을 정합니다.
  5. git pull --no-edit upstream main으로 자료를 받습니다. --no-edit는 기본 병합 메시지를 그대로 사용해 메시지 편집창을 생략합니다.
  6. Pull이 완료된 것을 확인한 뒤 git push origin main으로 자신의 포크에도 반영합니다.
터미널에 입력
명령 보기

명령은 한 줄씩 결과를 확인하며 실행합니다. 첫 줄의 설정은 현재 저장소에만 적용되며, 다음부터는 Pull 명령부터 실행하면 됩니다.

충돌이나 오류가 보이면

오류를 읽고 강사와 확인합니다. 기존 작업을 지우거나 저장소를 다시 Clone해서 덮어쓰지 않습니다.

받은 폴더에서 아래 파일을 브라우저로 엽니다.

01 · 무엇을 준비해야 하나요?

개인 발표 준비 안내

안내일: 2026년 9월 16일
발표일: 2026년 9월 23일

대학생이 공부하면서 겪는 불편 하나를 정해 주세요. 관련 AI 서비스 두 개를 살펴보고, 그 불편을 줄일 수 있는 자신의 개선안을 제안하는 발표입니다.

누가 어떤 상황에서 도움을 받는지 설명하는 데 초점을 맞춥니다. 각자 주제와 근거를 정리하고, 자신의 판단으로 발표자료를 완성해 주세요.

발표에 담을 내용

  1. 해결하려는 학습 상황과 구체적인 불편
  2. 두 서비스의 입력 자료, 도움을 주는 과정, 결과를 확인하는 방법
  3. 공식 자료에서 확인한 내용과 자신의 해석
  4. 기존 흐름에서 개선하고 싶은 지점과 제안 이유

자료를 정리할 때

서비스 설명에는 공개 공식자료를 최소 두 개 사용합니다. 발표에 쓴 설명과 그 근거가 되는 자료를 연결해 주세요.

직접 사용하지 않은 기능은 사용 후기처럼 표현하지 않습니다. 구현하지 않은 개선안은 제안 단계라고 밝히면 됩니다.

준비할 파일

표지와 출처를 포함해 4~6쪽으로 준비합니다. PDF로 저장한 뒤 다시 열어 글자가 잘리는 곳은 없는지, 링크가 열리는지 확인해 주세요.

출처목록.md

자료 제목, 제공 기관, URL, 확인일을 적습니다.

준비 목표

제출 경로는 별도 안내를 확인해 주세요. 파일을 준비한 상태와 실제로 전달한 상태는 구분해 기록합니다.

02 · 어떤 내용을 조사했나요?

자료의 근거를 확인하는 학습 도우미

자료 확인일: 2026년 9월 14일

내가 다루려는 문제

AI에게 요약을 받는 건 빠르다. 그런데 그 문장을 발표에 써도 되는지 확인하려면 원문을 다시 찾아야 한다.

자료를 찾은 뒤 근거를 확인하기까지, 두 서비스에서 어떤 과정을 거치는지 알아보고 싶다.

공식자료에서 확인한 내용

NotebookLM

Google의 2025년 소개 글에는 관심 주제로 웹 자료를 찾고, 추천 자료를 노트북에 추가하는 과정이 나와 있다. 추가한 자료의 원문을 읽고 채팅, 인용, 메모 기능을 활용할 수 있다고 한다. [S1]

내가 올린 파일만 다루는 서비스라고 설명하면 이 내용을 놓치게 된다.

Perplexity

공식 도움말은 질문을 이해하고 웹을 검색한 뒤 내용을 정리한다고 설명한다. 답변의 번호형 인용을 통해 원자료를 볼 수 있다. [S2]

출처 라벨에 대한 안내도 읽었다. 이 라벨은 개별 주장보다 웹사이트 전체의 특성을 설명하며, 원문 읽기를 대신하지는 않는다고 한다. [S3]

내 해석과 개선안

두 서비스 모두 근거를 살펴볼 연결점을 제공한다. 나는 자료를 골라 모아두는 과정과, 질문에서 웹 탐색을 시작하는 과정을 비교하려 한다. 어느 쪽이 더 정확한지는 공식 설명만으로 판단할 수 없다.

내가 원하는 것은 발표에 쓸 주장 옆에 근거 링크와 ‘직접 확인한 내용’을 남기는 조사노트다. 확인하지 않은 문장은 질문으로 모아두고 싶다.

기존 제품에 이런 기능이 없는지까지 확인한 것은 아니다. 우선 내 학습 과정에 필요한 작업 방식으로 제안하려 한다.

더 알아볼 것

같은 학습 질문을 넣으면 확인해야 할 원문은 어떻게 달라질까? 조사노트를 쓰면 확인 시간이 줄어들까? 아직 직접 측정하지는 않았다.

03 · 어디까지 했고 무엇이 남았나요?

내 발표 준비 메모

기록 기준: 2026년 9월 16일

이번에 전달하고 싶은 것

주제는 ‘자료의 근거를 확인하는 학습 도우미’로 정했다. AI 서비스 이름은 들어봤지만, 출처 확인에는 익숙하지 않은 대학생을 생각하고 있다.

답변을 받았을 때 무엇을 다시 확인하면 되는지 알려주고 싶다.

해 둔 일

공식자료 세 개를 읽고 주제조사메모.md에 핵심 내용을 적었다. 목차도 문제 소개, 서비스 비교, 개선안, 정리의 네 부분으로 잡아 두었다.

아직 발표 슬라이드는 만들지 않았다. 두 서비스에 같은 질문을 넣어 비교해 본 기록도 없다.

먼저 발표에 쓸 문장을 원문 근거와 하나씩 대조해야겠다.

남은 일과 고민

기능을 전부 소개하면 핵심이 흐려질 것 같다. 자료를 찾는 방식과 근거를 확인하는 방식으로 범위를 좁히고 싶다.

조사노트 개선안은 간단한 화면 그림으로 설명하려 한다. 아직 구현하거나 효과를 측정하지는 않았으니 그 점을 분명히 해야겠다.

남은 작업과 예상 시간은 준비작업.csv에 적었다.

내가 쓸 수 있는 시간

  • 목요일 저녁: 한 시간
  • 토요일 오전: 한 시간 반
  • 월요일 저녁: 한 시간 반
  • 화요일 오후: 마지막 점검을 위한 30분

금요일은 아르바이트, 일요일은 가족 일정이 있다. 작업 가능한 날짜와 시작·종료 시각은 작업가능시간.csv에 기록했다.

우선순위와 마지막 확인

예상보다 오래 걸리면 새 기능 조사를 늘리기보다 원문 대조와 개선안 설명을 먼저 마무리하고 싶다.

발표자료.pdf와 출처목록.md는 아직 없다. 제출 경로도 확인 전이다. 자료를 완성한 뒤 실제로 전달했는지는 따로 확인할 예정이다.

1. Python과 설치할 위치 확인

스크립트는 Python 3.10 이상을 사용합니다. Mac의 python3, Windows의 py -3 또는 python 중 실제로 실행되는 명령과 버전을 먼저 확인합니다. Kiro Crew 앱이 열려도 터미널의 Python은 따로 확인해야 합니다.

Python이 없거나 버전이 낮다면

Mac은 터미널에서 python3 --version, Windows는 터미널에서 py -3 --version을 입력합니다. Windows에서 py를 찾지 못하면 python --version도 확인합니다. Python 3.10 이상이 표시되면 그 명령을 사용합니다.

  • Mac: Python 공식 다운로드에서 macOS용 정식 버전의 .pkg를 받아 실행합니다.
  • Windows: 같은 공식 다운로드에서 Python Install Manager를 설치합니다. 새 터미널을 열고 py install 3.14로 Python을 준비합니다.

설치 후 터미널을 새로 열어 위 버전 명령을 다시 확인합니다. 터미널에서는 되는데 Crew에서 찾지 못하면 작업을 저장하고 Crew를 다시 열어 확인합니다. 여전히 실패하면 실행한 명령과 오류 문구를 강사에게 보여 주세요.

수업 코드에는 추가 Python 패키지가 필요 없습니다. 설치 세부 안내: Mac · Windows

2. 전용 템플릿 선택 → 스킬 연결 → 적용

크루와 에이전트 템플릿은 구분합니다

kirocrew 템플릿은 다른 크루도 사용할 수 있습니다. 기존 템플릿을 유지하고, 복사한 kmu-w03 템플릿에 이번 스킬을 연결합니다.

  4. 스킬 목록을 새로고침해 kmu-w03-prep-check를 찾습니다. 목록에 없으면 적용 후 재시작한 뒤 스킬을 다시 새로고침합니다.
