# 발표 준비 점검

발표 안내, 조사 메모, 개인 준비 메모를 읽고 다음에 할 일을 정리한다. 작업시간 합산과 가용시간 계산은 함께 제공된 `scripts/check_plan.py`를 실행한다. 계산 결과를 읽지 않고 숫자를 추정해 채우지 않는다.

## 입력과 결과

- 사용자가 지정한 자료와 저장 위치를 우선한다. 별도 지정이 없으면 현재 프로젝트의 국민대 AI플랫폼개발 `week03` 폴더를 확인한다. 저장소 최상위를 연결했다면 `class/kookmin-2026-2/ai-platform-development/week03`이며, 해당 폴더 자체가 연결돼 있을 수도 있다. 후보가 여러 개이거나 찾지 못하면 사용자에게 확인한다.
- 발표 안내와 조사 메모는 `data`에서 읽는다. `submissions`에 개인 준비 메모와 두 CSV가 모두 있으면 그 사본을 사용한다. 개인 사본이 전혀 없으면 `data`의 자료를 사용한다. 일부만 있거나 어느 사본이 최신인지 불분명하면 확인하고, 개인 자료와 원본을 임의로 섞지 않는다.
- 기준 시각과 마감 시각을 요청과 자료에서 확인한다. 같은 준비 계획을 재점검하며 새 기준 시각을 지정하지 않았다면 직전 계산 JSON의 기준 시각을 유지하고 결과에 밝힌다. 확인할 수 없는 시각은 사용자에게 묻고 임의로 정하지 않는다. 시각에는 `+09:00` 같은 시간대가 필요하다.
- 기존 준비 계획과 추가 안내가 있으면 함께 읽는다.
- 결과는 계산 JSON·HTML, 준비 계획 Markdown이다. 기본 저장 위치는 해당 `week03/submissions`이며, 파일 이름은 `발표준비점검.json`, `발표준비점검.html`, `준비계획.md`이다. 입력 자료와 다른 경로를 쓴다.
- 추가 안내를 반영한 재점검은 기존 결과를 보존하고 `발표준비점검_추가안내.json`, `발표준비점검_추가안내.html`, `준비계획_추가안내.md`로 저장한다. 같은 이름의 결과가 이미 있으면 번호를 붙여 새 파일로 남긴다. 사용자가 기존 결과 갱신을 명시한 경우에는 그 요청을 따른다.

## 수행 순서

1. 안내의 제출 요구와 조사·준비 상태를 대조한다. 초안 작성, 파일 저장, 실제 제출을 구분한다. 누락을 지적하기 전에 문서 상단의 공통 정보와 하단의 출처 목록도 확인한다. 근거가 부족하면 확인할 질문으로 남긴다.
2. CSV가 메모와 맞는지 확인한다. `remaining_minutes`는 남은 작업의 예상 소요시간이며, 작업자는 이 예상값과 자기 가용시간을 검토해야 한다. 수정이 필요하면 사용자와 확인한 사본을 만들어 계산한다.
3. 현재 환경의 Python 3.10 이상 실행 명령을 확인한다. Mac의 `python3`, Windows의 `py -3` 또는 `python` 중 실제 동작하는 명령을 쓴다. 실행파일 설치만으로 터미널의 Python이 준비됐다고 가정하지 않는다.
4. 실행용 스킬 폴더는 사용자 홈의 `.kiro/crew/skills/kmu-w03-prep-check/`이다. 먼저 이 폴더와 `scripts/check_plan.py`의 존재를 확인하고 아래 도구를 실행한다. 다른 위치에 설치했다면 확인된 설치 경로를 사용한다. 원본 배포 폴더와 실행용 폴더를 혼동하지 않는다. 절대 경로를 따옴표로 감싸 공백·한글 경로를 처리한다. Windows에서도 동일한 인수를 전달한다.

```text
python3 "<이 스킬 폴더>/scripts/check_plan.py" --tasks "<준비작업.csv>" --availability "<작업가능시간.csv>" --as-of "<기준 ISO 시각>" --deadline "<마감 ISO 시각>" --output "<결과 폴더>/발표준비점검.json" --html "<결과 폴더>/발표준비점검.html"
```

5. 종료 코드와 실제 저장 파일을 확인한다. 입력 오류가 나면 원인을 설명하고 입력 사본을 바로잡는다. 실행 실패 상태에서 계산 완료라고 보고하지 않는다.
6. JSON의 `summary`와 `merged_windows`를 읽어 부족 시간, 이미 끝낸 일, 다음 행동을 정리한다. 시간 총량이 충분해도 작업 순서·의존 관계·집중 가능 여부 때문에 계획을 조정할 수 있다. 이 판단과 숫자 계산을 구분한다.
7. 자료의 근거, 현재 상태, 다음 행동, 확인할 질문을 담은 준비 계획을 지정된 출력 폴더에 저장한다. 기존 계획을 갱신할 때는 달라진 요구와 사용자 개인 조건을 대조하고 유지할 내용을 보존한다.

## 도구의 입력 규칙

`준비작업.csv`의 열은 `task_id,task,remaining_minutes,status`이다. ID는 중복되지 않고, 남은 분은 0 이상의 유한한 숫자다. 상태는 `todo`, `in_progress`, `done` 중 하나이며 `done`은 남은 분이 0이다.

`작업가능시간.csv`의 열은 `start,end,label`이다. 시작·끝은 시간대가 있는 ISO 시각이고 끝이 시작보다 뒤여야 한다. 헤더만 있으면 가용시간 0분으로 계산한다.

도구는 기준 시각부터 마감까지 구간을 자른 뒤 겹친 시간을 한 번만 계산한다. 원본은 읽기만 하고, 실행마다 출력 경로를 명시한다. 계산값은 입력된 예상에 대한 결과이며 실제 완료를 보장하지 않는다.

## 결과를 전달할 때

사용자가 지금 무엇을 하면 좋을지 먼저 설명한다. 준비 상태, 시간 비교, 다음 행동을 짧은 문단으로 나누고, 사용자가 결정할 내용이나 확인할 질문을 이어서 적는다.

남은 작업과 가용시간은 읽기 쉬운 한두 문장이나 작은 표로 보여준다. 상태 코드는 한국어로 풀어 쓰고, 같은 정보를 여러 목록으로 반복하지 않는다.

사용한 입력과 만든 결과는 짧은 파일 이름으로 안내한다. 실제 경로를 검증하고 실행한 명령은 실행 기록에 남기되, 매번 본문에 전체 명령·작업 디렉터리·긴 절대경로를 나열하지 않는다. 사용자가 실행 내용을 요청하거나 오류 해결에 필요할 때 해당 부분을 보여준다.
