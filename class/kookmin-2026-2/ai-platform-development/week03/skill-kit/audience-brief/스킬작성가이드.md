# 청중에 맞춰 설명하는 나의 스킬

동아리 1학년 후배와 교수님은 같은 내용을 들어도 궁금해하는 것이 다릅니다. `data/주제조사메모.md`를 바탕으로 두 청중에게 설명하는 자료를 만들어 보세요. 사실은 유지하면서 용어, 설명 순서, 예시, 근거를 제시하는 깊이를 조절합니다.

기본 청중 A는 ‘동아리 1학년 후배’, B는 ‘교수님’입니다. 시작하기 화면에서 자신이 실제로 설명하고 싶은 다른 청중을 선택해도 됩니다. 선택한 청중의 배경과 궁금해할 내용을 구체적으로 정하세요.

이 폴더에는 원고를 HTML로 조립하는 도구와 양식이 준비되어 있습니다. **스킬의 판단 기준과 작업 순서를 담을 `SKILL.md`는 직접 만듭니다.** Crew와 함께 초안을 작성해도 됩니다.

## 먼저 정할 세 가지

1. 후배가 처음 듣는 내용은 무엇이며, 어떤 익숙한 상황에서 설명을 시작할까요?
2. 교수님 앞에서 어떤 주장과 근거를 분명히 하고, 어떤 한계를 설명할까요?
3. 두 설명이 같은 사실을 유지했는지 무엇을 대조할까요?

두 버전은 본문 3단락, 단락마다 2문장으로 작성하고 전체 분량도 비슷하게 맞추세요. 단순히 말투만 바꾸는 데서 멈추지 말고, 본인이 직접 읽고 전달할 수 있는 설명으로 다듬습니다. 이 분량과 설명의 적절성은 원고 검토 단계에서 확인합니다.

## 지침과 코드가 맡을 일

| 구성 | 역할 |
|---|---|
| 내가 작성할 `SKILL.md` | 언제 사용할지, 무엇을 입력받을지, 청중별 작성 기준과 검토 순서 |
| `scripts/build_handout.py` | 공통근거와 사실·출처의 값과 순서를 대조하고, HTML 문자를 안전하게 처리해 고정 양식으로 조립 |
| `templates/handout.html` | 화면과 인쇄에 사용할 공통 출력 양식 |

코드가 내용의 진실성이나 청중에게 적절한지를 판단하지는 않습니다. 본문 3단락·단락마다 2문장 조건도 자동 검사하지 않습니다. 코드 실행 전후로 원문과 의미, 분량을 직접 확인해야 합니다.

## SKILL.md에 담을 내용

- 이름은 `kmu-w03-audience-brief`로 정합니다. 파일 맨 위 YAML 영역에 `name`과 어떤 요청에 쓰는지를 설명하는 `description`을 넣습니다.
- 입력으로 조사 메모, 청중, 설명 목적, 분량, 출력 위치를 받도록 정합니다.
- 앞서 결정한 청중별 설명 기준을 자신의 문장으로 적습니다.
- 출처가 설명하는 시점, 자료를 읽은 확인일, 작성자의 해석·제안을 어떻게 구분할지도 정합니다. 쉽게 설명하는 과정에서 원문의 조건을 없애지 않습니다.
- 먼저 검토한 사실과 출처를 `submissions/공통근거.json`에 한 번 정리합니다. 구조는 `facts`와 `sources` 두 목록입니다.
- 청중별 원고 JSON에서 `title`(제목), `audience`(설명 대상), `sections`의 `heading`·`body`·`source_ids`(소제목·본문·관련 출처)는 청중에 맞춰 바꿉니다. `source_ids`에는 등록된 출처 ID만 씁니다. `facts`와 `sources`는 공통근거 파일의 객체 전체 값과 목록 순서를 그대로 유지하며 추가 필드도 생략하지 않습니다.
- 아래 도구를 `--evidence`와 함께 실제로 실행하고 생성된 파일을 확인하는 절차를 포함합니다. 실행에 필요한 코드를 매번 새로 쓰게 하지 않습니다.
- 실패 시 입력·출처 ID·경로를 확인하도록 하고, 어떤 결과를 얻어야 완료인지 정합니다.

## 제작 도구의 입력 계약

청중별 JSON 파일에는 다음 항목이 필요합니다.

| 항목 | 형식 |
|---|---|
| `title` | 자료 제목 문자열 |
| `audience` | 설명 대상 문자열 |
| `sections` | `heading`, `body`를 가진 객체 목록. 관련 출처가 있으면 `source_ids` 문자열 목록 추가 |
| `facts` | `id`, `text`를 가진 객체 목록. 두 청중의 공통 사실 원문 |
| `sources` | `id`, `title`, `url`을 가진 객체 목록. 실제 확인한 http/https 출처 |

`source_ids`의 값은 `sources`의 ID와 일치해야 합니다. 도구는 출처 입력 순서에 따라 번호를 정하고, 본문에서 같은 출처를 참조하면 같은 번호를 붙입니다. URL의 존재나 내용까지 확인하지는 않습니다. `facts`와 `sources`는 두 파일에서 같은 값과 순서를 유지합니다.

이 수업에서는 두 원고 모두 `--evidence`로 같은 `공통근거.json`을 지정합니다. 그러면 각 원고의 `facts`, `sources`가 공통근거 파일과 같은 값·순서인지 코드가 검사하고, 다르면 HTML을 만들지 않고 오류를 알립니다. 검토한 원고 본문이 그 사실을 올바르게 설명하는지는 여전히 직접 확인해야 합니다.

## 실행 명령

확인된 Python 3.10 이상 명령을 사용합니다. Mac은 보통 `python3`, Windows는 `py -3` 또는 `python`입니다. 이 명령들은 먼저 해당 환경에서 확인해야 합니다.

```text
python3 "<내 스킬 폴더>/scripts/build_handout.py" --input "<프로젝트>/submissions/청중A_원고.json" --evidence "<프로젝트>/submissions/공통근거.json" --template "<내 스킬 폴더>/templates/handout.html" --output "<프로젝트>/submissions/청중A_설명.html"
```

청중 B용은 입력을 `청중B_원고.json`, 출력을 `청중B_설명.html`로 바꿔 같은 코드를 실행합니다. 경로는 실제 프로젝트와 스킬 폴더 경로로 바꾸고 공백·한글 경로를 따옴표로 감쌉니다.

## 직접 확인하고 보완하기

1. 만든 `SKILL.md`를 읽고 자기 기준이 들어 있는지 확인합니다.
2. `SKILL.md`, `scripts`, `templates`를 포함한 폴더 전체를 수업 안내의 실행용 스킬 위치에 설치하고 자신의 크루에 연결합니다. 배포용 레포에 파일을 넣은 것만으로 연결됐다고 생각하지 않습니다.
3. 새 세션에서 스킬을 호출해 두 버전을 만듭니다. 실행한 스크립트 경로와 저장된 HTML을 확인합니다.
4. 두 번 모두 같은 `공통근거.json`을 `--evidence`로 지정해 값·순서 검사를 통과했는지 확인합니다. 사실을 고칠 필요가 있으면 먼저 근거를 다시 검토하고 공통근거와 두 원고를 함께 갱신합니다.
5. HTML을 열어 청중별 차이가 도움이 되는지 읽어 봅니다. 실제 실행에서 발견한 개선점 하나를 스킬에 반영합니다.

사용자 데이터 전체를 레포에 복사하지 않습니다. 제출할 것은 자신의 스킬 폴더와 생성한 결과·검토 기록입니다.
